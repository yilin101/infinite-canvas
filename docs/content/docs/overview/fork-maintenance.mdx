# 二开维护

本文档记录当前个人分支的长期维护方式：保留自定义功能，定期同步原项目更新，并把镜像部署到宝塔服务器。

## 分支关系

当前仓库作为个人维护版使用：

- `origin`：你的 GitHub 仓库，例如 `yilin101/infinite-canvas`
- `upstream`：原项目 `basketikun/infinite-canvas`

本分支的自定义功能应先提交到 `origin/main`，再同步 `upstream/main`。这样 Git 可以识别哪些是本分支的改动，哪些是原项目新增功能。

## 同步原项目

推荐在 GitHub Actions 里手动运行 `Sync upstream` 工作流。它会拉取原项目 `main` 分支，创建同步分支，并自动发起 Pull Request。

如果没有冲突：

1. 打开 GitHub Pull Request。
2. 检查变更。
3. 合并到 `main`。
4. 等待 Docker image 工作流发布新镜像。

如果有冲突：

1. 在 PR 页面查看冲突文件。
2. 优先保留本分支的自定义功能。
3. 重点检查图片节点工具栏相关文件。
4. 本地测试后再合并。

本分支比较容易冲突的文件：

```text
web/src/app/(user)/canvas/components/canvas-image-toolbar-tools.tsx
web/src/app/(user)/canvas/components/canvas-node-hover-toolbar.tsx
web/src/app/(user)/canvas/[id]/canvas-client-page.tsx
```

## 本地手动同步

也可以在本地执行：

```bash
git remote add upstream https://github.com/basketikun/infinite-canvas.git
git fetch upstream
git checkout main
git pull origin main
git merge upstream/main
```

解决冲突后提交：

```bash
git add .
git commit
git push origin main
```

## Docker 镜像

`.github/workflows/docker-image.yml` 会在 `main` 分支更新后构建并推送：

```text
ghcr.io/yilin101/infinite-canvas:latest
```

打 tag 时也会发布对应版本号镜像。

如果宝塔服务器拉取镜像提示没有权限，有两种处理方式：

- 在 GitHub 仓库的 Packages 页面把 `infinite-canvas` 包设置为 Public。
- 或者在服务器执行 `docker login ghcr.io`，使用 GitHub 用户名和有 `read:packages` 权限的 Personal Access Token 登录。

## 宝塔部署

服务器目录建议：

```text
/www/wwwroot/infinite-canvas
```

首次部署：

```bash
cd /www/wwwroot/infinite-canvas
docker compose -f docker-compose.server.yml up -d
```

部署前先在 `docker-compose.server.yml` 里修改登录账号和默认 AI 配置：

```yaml
environment:
  APP_AUTH_ENABLED: "true"
  APP_AUTH_USERNAME: "admin"
  APP_AUTH_PASSWORD: "请修改为强密码"
  APP_AUTH_SECRET: "请修改为随机长字符串"
  APP_AUTH_DISPLAY_NAME: "管理员"
  APP_AUTH_COOKIE_SECURE: "false"
  APP_DEFAULT_API_FORMAT: "openai"
  APP_DEFAULT_API_BASE_URL: "https://api.openai.com"
  APP_DEFAULT_API_KEY: "你的 API Key"
  APP_DEFAULT_IMAGE_MODEL: "gpt-image-2"
  APP_DEFAULT_IMAGE_SIZE: "1:1"
  APP_DEFAULT_IMAGE_QUALITY: "auto"
  APP_DEFAULT_IMAGE_COUNT: "1"
  APP_DEFAULT_CANVAS_IMAGE_COUNT: "3"
```

默认会要求登录后才能使用。登录成功后，网页会把服务器配置的默认 Base URL、API Key、模型和图像默认参数写入浏览器本地配置；如果已经在网页里手动配置过 API Key，刷新页面不会自动覆盖。

如果你的站点已经全站 HTTPS，可以把 `APP_AUTH_COOKIE_SECURE` 改成 `"true"`；如果还在用 HTTP 或宝塔内网反代，保持 `"false"`，否则浏览器可能不会保存登录 Cookie。

如果要使用“上传图床”，先在 `docker-compose.server.yml` 里填写图床 Token：

```yaml
environment:
  IMAGE_HOST_UPLOAD_URL: "http://amzimg.bizzlife.top/api/v1/upload"
  IMAGE_HOST_METHOD: "POST"
  IMAGE_HOST_FIELD: "file"
  IMAGE_HOST_TOKEN: "你的图床 token"
```

图床 Token 固定使用 Bearer Auth，服务端会自动带上 `Authorization: Bearer <IMAGE_HOST_TOKEN>`。如果误把 `IMAGE_HOST_UPLOAD_URL` 写成 `http://amzimg.bizzlife.top/api/v1`，服务端遇到 405 时会自动重试 `/upload`；仍失败时会返回更短的错误提示，避免把整段 HTML 错误页显示到前端。

网页里进入右上角“配置与用户偏好 -> 图床”，填写返回域名，例如：

```text
http://kidn.brp2o0stwv.xin
```

上传成功后会复制替换域名后的链接；未填写返回域名时不会上传，也不会返回原始图床域名。

更新部署：

```bash
cd /www/wwwroot/infinite-canvas
docker compose -f docker-compose.server.yml pull
docker compose -f docker-compose.server.yml up -d
```

查看日志：

```bash
docker logs -f infinite-canvas
```

宝塔网站反向代理目标：

```text
http://127.0.0.1:3000
```

建议在 Nginx 站点配置中加入：

```nginx
client_max_body_size 50m;
```

## 回滚

如果最新镜像有问题，可以先在 GitHub Actions 找到上一个可用的 tag 或 sha 镜像，把 `docker-compose.server.yml` 中的镜像 tag 临时改成旧版本，然后执行：

```bash
docker compose -f docker-compose.server.yml up -d
```

确认问题后再修复 `main` 并重新发布 `latest`。
